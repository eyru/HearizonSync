## 为什么做这个

英文课最难受的地方不在听不懂单词，而在每个词都认识、连成一句就断片。会开完了，笔记是空的。

市面上的方案分两类：云端听写要联网、要订阅、音频还得先上传；离线的只做听写，不翻译，等于把断片的问题原样留给你。

Hearizon Sync 的取舍很明确——**识别全部压在本机，翻译给你三条互不干扰的路，自己选**。选便宜的、选免费的、选质量最高的，都由你决定，程序不会替你花钱，也不会背着你联网。

## 一条完整的处理链

```
麦克风 ──► 能量 VAD 断句 ──► SenseVoice 本地识别 ──► 翻译 ──► 双栏字幕
           说完静音 700 ms 起        原文/语言/情感      三选一       上原文下译文
```

音频只进不出。识别引擎在本地跑完，才把**识别出的文本**交给翻译层；选本地翻译时，连文本都不出本机。

| 环节 | 技术选型 | 耗时（Ryzen 9 9955HX） |
|---|---|---|
| 采集 | `sounddevice`，16 kHz 单声道 | — |
| 断句 | 能量门限 VAD（RMS 0.008）+ 700 ms 静音挂起 | — |
| 识别 | SenseVoice-Small（ONNX Runtime） | **0.17 s / 10 s 语音**，RTF 0.018 |
| 翻译 | 本地 opus-mt / 免费在线 / DeepSeek API | 0.03 s ~ 0.9 s |
| 呈现 | Tk 自绘双栏字幕，流式出字 | 首字延迟约 0.3 s |

## 三条翻译路线（v2.5.5 起）

从这一版开始，翻译被拆成三条**完全独立**的路线，彼此之间没有任何"自动降级"。你选哪条，就走哪条。

| 路线 | 联网 | 成本 | 可用语言 | 定位 |
|---|---|---|---|---|
| **本地翻译（离线）** | 否 | ¥0 | 英 → 中 | 断网、飞行模式、保密场合的唯一选择 |
| **在线翻译（免费）** | 是 | **¥0** | 中/英/日/韩/德/法/意/西 | 开箱即用，一分钱不花，不需要任何账号 |
| **API 模式（付费）** | 是 | 按量计费 | 全部语言对 | DeepSeek 大模型 / 有道智云，质量最高 |

切换路线时，当前路线用不了的语言会在下拉框里**变灰、点不动**，并自动把当前选择纠正到可用项——不会让你选出一个必然失败的组合。

### 为什么 API 模式必须手动选

因为 API 是**花真钱**的。程序不会在你不知情时把句子送去计费接口，也不会偷偷读取机器上其他软件的凭据。

选中 API 模式时，状态栏会明确显示：

```
API模式启动，auto功能失效
```

同时自动打开自动纠错（付费模式下这一步是必要工序）。反过来，如果你在本地/免费模式里手动勾选「自动纠错」，会先弹出提示：**这个功能会消耗 API 余额**，并提供一个「不再提醒」勾选框。

## 免费在线：凭什么敢说"任何电脑都能用、一分钱不花"

这条路线是本项目最费劲的部分。目标只有一句：**不注册、不绑卡、不用 VPN、在中国大陆的家用宽带上直接可用**。

为此我把候选接口逐个打通实测，结果如下：

| 接口 | 大陆直连 | 结论 |
|---|---|---|
| **MyMemory**（最终采用） | 可以 | 18/18 句全成功；英→中/日/韩/德/法/西/意、中→英/日 整句质量可用 |
| 有道免费网页接口 | 可以 | 仅支持「译成中文」；约 6 次/分钟触发 `411` 限频，冷却 60 s 恢复 |
| Google 翻译接口 | **不可达** | 境内需代理，直接排除，绝不把翻墙当作运行前提 |
| 金山 iciba 旧接口 | 可以 | 已下线，返回 HTML，不可用 |

最终方案是**单一免费引擎 MyMemory**，配一条全程免费的兜底链：

```
MyMemory（任意目标语言）
   └─ 额度耗尽 / 网络抖动 ──► 有道免费接口（仅译成中文）
          └─ 仍不可用 ──────► 本地 opus-mt（仅英→中，纯离线不限量）
```

额度账也算清楚，写在设置页里：

| 项目 | 额度 | 折算时长 |
|---|---|---|
| 匿名使用 | 5000 字符/天 | 约 30~40 分钟连续讲话 |
| 填一个邮箱（只作为 `de` 参数提交） | **50000 字符/天** | 约 5~6 小时 |

用满当天额度不会报错、不会中断字幕，只会安静地降到下一级兜底，次日自动恢复。对讲座、网课这类场景，填个邮箱基本够一整天的课。

## API 模式：接入 DeepSeek 大模型

如果对译文质量有要求，这一层是目前能拿到的最好结果。

**DeepSeek**：整句交给大模型翻译，走流式接口（`stream: true`），收到一个字就显示一个字。实测一句 40 词英文，从请求到出完整译文约 **0.9 s**，同传节奏下完全跟得上。它比传统 NMT 强的地方在于上下文和口语处理——半句话、语气词、省略主语，都能按"人会怎么说"来还原，而不是逐词硬对。

**有道智云**：作为 API 模式里的第二引擎，支持 `medicine`、`computers`、`finance` 等领域参数，专业文献的术语更稳。

### API 引擎怎么选（v2.5.5）

两个 Key 都配好时，由「API 引擎」下拉决定实际用谁：

| 选项 | 行为 |
|---|---|
| DeepSeek | 只用 DeepSeek；没配 Key 会直接提示 |
| 有道智云 | 只用有道；可指定领域，适合专业文献 |
| **自动兜底**（默认） | DeepSeek 优先；若一个字都没输出就失败，自动改用有道，并在状态栏提示 |

选中 API 模式时状态栏显示「API模式启动｜当前引擎」，不再出现历史遗留的 auto 提示。这个下拉只在 API 模式下可用，其它模式自动置灰。

两个 Key 都只从**你自己**的地方读：

1. 环境变量 `DEEPSEEK_API_KEY`，或
2. 程序设置页里填（存在 `~/.hearizon_sync.json`，只有你自己的账户看得到）

没有 Key 就明说没有 Key，绝不去别的软件目录里翻凭据。这一条是 v2.5.1 的硬性要求，原因写在下面的版本历程里。

## 识别引擎

| 输入语言 | 实际引擎 | 依据 |
|---|---|---|
| 自动检测 / 中文 / 英语 / 粤语 | **SenseVoice** | 中文原生训练，CER 约 8%，最快 |
| 日语 / 韩语 | Whisper | 本版 sherpa-onnx 的 `language` 参数实测无效，日韩会被误判 |
| 德语 / 法语 / 意大利语 / 西班牙语 | Whisper | SenseVoice 模型本身不含这些语种 |

除原文外，SenseVoice 还会输出说话人情绪与音频事件标签（笑声、掌声、音乐等），在字幕行尾以 `[HAPPY]`、`[LAUGHTER]` 这类形式附带显示，方便回看时定位氛围。

## 工程上真正麻烦的地方

这一节记录踩过的坑。它们决定了代码为什么长成现在这样。

**`sentencepiece` 打不开中文路径。** 它的 C++ 层用窄字符打开文件，路径里有中文就报 `NOT_FOUND`，即使文件明明在那里。所以本地翻译模型强制 ASCII 路径优先，打包后落在 `_internal/models/`，源码运行时可指向 `D:\slm-models\`。

**Marian 模型必须在源端补 `</s>`。** 少这一个 token，输出会陷入重复循环，翻出来是"你能听到你能听到你能听到"。这个 bug 靠肉眼读代码绝对看不出来，只能跑出来才知道。

**系统托盘没有引第三方库。** `pystray` 会再拖进一个 GUI 依赖树，为一个图标不值得。最终用纯 `ctypes` 调 `Shell_NotifyIconW`：建隐藏窗口、写 `WndProc`、收托盘消息。代价是要给每个 Win32 函数显式声明 `argtypes`，否则 64 位下句柄会被截断成 `OverflowError`。

**界面控件全部自绘。** Tk 原生控件在深色主题下没法看，`ttk` 也只能改局部。圆角按钮、圆角复选框、下拉弹层、滚动条，都是自己在 `Canvas` 上画的——包括那个"当前模式用不了的语言置灰且不可点"的下拉项状态。

**GPU 探测要判断三件事。** 有显卡、驱动装了、CUDA 运行时齐了，是三个不同的问题。`ctranslate2.get_cuda_device_count()` 只回答第一个，所以还要查 `nvidia-smi` 和 WMI 显卡列表，最后真跑一次推理确认 `cublas64_12.dll` 能加载。

**安装包为什么要做到 367 MB。** 识别模型 239 MB、本地翻译模型 155 MB，加上 Python 运行时和 ONNX/CTranslate2。可以把模型做成首次启动时下载，但那样"断网也能用"和"装完即用"两条承诺就同时破了。宁可大，不可残。

## 安装

### 方式一：安装包（推荐）

1. 到 [Releases](../../releases) 下载 `HearizonSync-Setup-3.0.0-pre2.exe`（约 367 MB）
2. 双击安装，默认路径 `C:\Program Files\Hearizon Sync`
3. 开始菜单或桌面启动

安装包内含 Python 运行时、识别模型、本地翻译模型，**装完即可用，不需要再装任何东西**。

### 在线更新（v2.5.5起）

程序启动 4 秒后会**静默检查** GitHub 上有没有新版本：

- 有新版本 → 弹窗介绍本版更新内容，可点「稍后提醒」取消，也可勾选「跳过这个版本」
- 点「下载并安装」→ 后台下载安装包（显示进度，期间可继续使用）
- 下载完成 → 询问是否安装；确认后关闭程序并启动安装程序

**升级是覆盖安装，你的设置、API Key、字幕偏好都保存在 `~/.hearizon_sync.json`，不会被清掉。** 不想让它检查，可在设置页关掉「启动时检查更新」。

### 界面清晰度（v2.5.5起）

v2.5.5 声明了进程 DPI 感知并按屏幕真实 DPI 缩放：高分屏（125% / 150% / 200%）下字体、自绘控件、窗口尺寸一起放大，不再被 Windows 当位图拉伸成模糊一片。

### 方式二：从源码运行

需要 Python 3.12：

```bash
git clone https://github.com/eyru/HearizonSync.git
cd HearizonSync
python -m venv .venv
.venv\Scripts\activate
pip install sherpa-onnx ctranslate2 sentencepiece sounddevice numpy faster-whisper
```

再按下方「模型下载」放好两个模型，然后：

```bash
python src/HearizonSync.py
```

## 使用

左侧从上到下依次是：输入语言、音频输入、译成、翻译模式、识别引擎，再到 GPU 加速与自动纠错开关。

**三步开始**：选麦克风（点「测麦克风」可验证电平）→ 选输入语言和译成 → 点「开始同传」。

| 快捷键 | 功能 |
|---|---|
| `Ctrl+Enter` | 开始 / 停止同传 |
| `Ctrl+L` | 清空字幕 |
| `Ctrl+S` | 保存记录（原文 + 译文） |
| `Ctrl+Shift+S` | 导出 SRT（真实时间轴） |
| `Ctrl+ +` / `Ctrl+ -` | 调整字幕字号（14~32 pt） |

## v3.0.0 更新

3.0 不是加功能，是把「听得清」这件事从算法层重做了一遍。

过去的识别增强是若干临时补丁的叠加：自适应门限是一处、远场增益是另一处、降噪又是第三处，
三处各自调参、各自失效。3.0 把它们换成一个统一的处理核心——**HAE-NSG Core**（Hearizon
Audiology Engine — Noise-Suppression Gain Core），并且这个核心是独立开源的，Python 与 C++
两套实现逐位一致。

### 音频前端重写（回灌 HAE-NSG Core）

这是本版最重要的改动。旧的增强链路有一个隐蔽缺陷：增益按语音电平计算，却作用在整段音频上，
于是**静音段被和语音一样放大**——实测底噪放大了 8 倍。听起来就是「嘶——」一直在响。

新链路把三件事解耦：

- **增益只对语音段负责**，静音段由噪声门单独压制
- **噪声门用两簇判决**（一维 k-means 把分析块的能量分成「语音簇」与「噪声簇」），
  而不是分位数阈值——分位数会把一半静音帧漏判成语音
- **静音段的最终倍数固定为门限衰减值**，与增益无关。这一条是关键：如果只做「不放大」，
  静音段保持原样，净效果是「没变得更吵」而不是「变安静了」

实测同一段 4 秒录音（前半语音、后半纯底噪）：

| | 底噪 RMS | 倍数 |
|---|---|---|
| 原始 | 0.00399 | — |
| 旧链路 | 0.03196 | **8.00×（放大了）** |
| 新链路 | 0.00148 | **0.37×（降 8.6 dB）** |

语音段同时被抬到 15.56 倍。三个预设的输出与 `hae_nsg.process` 逐位一致，有 17 项测试盯着。

### 识别更稳

- **口音与快语速**：显式锁定输入语言后不再让模型自己猜，精度档位放开到 `medium` / `large-v3-turbo`
- **短句被拦腰截断**（把 *Spanish* 听成 *fan*）：断句点改为向能量谷底吸附，不再切在音节中间。
  这一条现在由独立的 **HAE-VAD Core** 负责，同样是双实现、可单独使用
- **流式识别的回退修正**：滑动窗口重识别时模型偶尔会推翻已念对的前半段，字幕来回跳。
  现在做前缀稳定性判定——分叉点靠前的改动要连续两次一致才刷新，正常延伸立即显示
- **远场模式**（5 米以上）与**强制放大分贝**（极小声）：两档可选的激进增强

### 翻译更顺

- **译文不再突然变繁体**：中文目标下统一转简体（内置字表，不联网）
- **带上下文翻译**：最近 3 轮原文/译文一起交给模型，跨句指代和省略能接住了
- **自定义 API 地址**：可指向中转站或自建网关
- **流式同传**：边说边出字，灰色临时行不翻译，稳定后转正

### 界面

- 新增「对话」布局（气泡流），经典左右分栏一分没动
- 设置页支持滚动（选项已多到一屏放不下，底部按钮以前直接看不见）
- 更新弹窗不再锁死主窗口
- 六个独家模块全部可触发，触发词仍以码点拼装，源码里没有明文

- **下载进度更清楚**：显示「已下载 / 总量」、实时速度和预计剩余时间

## v2.5.6 更新

**识别历史**：修复「原文永远只有一条」的问题——临时流式行的清理标记位置有误，会在下一句开始时把已有历史整段删掉。现在每句都正常累积。

**识别引擎增强（对所有用户生效）**：三项通用改进——自适应噪声门限（按环境噪声自动调整，安静时不迟钝、嘈杂时不乱切）、远场增益归一（说话人离得远时把整句拉到可识别电平，限制最大增益以免放大底噪）、句尾降噪（按帧估计噪声底，只衰减明显低于噪声底的帧，语音主体不动，实测底噪降低约 56%、语音保留 100%）。另提供**自定义热词**：在设置里填你常说的专业词或人名，识别会偏向这些词并纠正高度相似的同音错字；留空则不做任何词表干预，程序不预置任何领域词。

**代码与注释精简**：注释去掉序号符号与警告图标，合并重复的弹窗样板与设置页表单代码。

**独家模块**：四个隐藏入口统一命名（模块 1、2、2-1、2-2），触发词改为码点拼装，源码中不再出现明文，照抄代码也无法直接得到触发方式。

## 版本历程

**v1.0.x —— 先让它跑起来**
目标只有一个：麦克风说一句，屏幕上能出现一句翻好的中文。SenseVoice 接上，模型加载，字幕能滚。丑，但能用。

**v1.1.0 —— 小语种互译计划**
这一版的起点来自 **Zhu-Ruijie（北京语言大学）** 的提议：只做英译中太窄，出国交换、看日剧、做多语种田野调查的人用不上。于是加入输入语言选择，把 Whisper 接进来补齐德/法/意/西，日/韩也交给它。也是这一版发现：sherpa-onnx 的 SenseVoice `language` 参数形同虚设，日韩会被稳定误判成日语——只能换引擎绕过去。

**v2.0.1 —— 界面推倒重做**
上一版的界面难看到自己都不愿意打开。这一版把 Tk 原生控件全换掉：圆角按钮、自绘下拉、现代滚动条、可滚动侧栏；字幕做三套配色和贴底/贴顶；加系统托盘、SRT 真实时间轴导出。功能没多，但终于像个正经软件。

**v2.1.1 —— 自动纠错，也埋了坑**
识别之后、翻译之前插一道最小修正（标点与重复字规则 + 云端 LLM 兜底），专门治同音错字与口吃重复。同时修了 Program Files 无写权限导致保存失败、关于页按钮被彩蛋压扁等一堆小问题。这一版埋了两个当时没意识到的坑：GPU 失败的提示文案是写死的；API Key 会去读机器上别的软件的凭据。当时只在开发机上测，两个坑都躲过去。

**v2.2.x —— 云端接入的内部迭代（未单独发版）**
这段时间翻译时好时坏，用户反馈集中在"有时候翻、有时候不翻"。内部反复重试、降级、再重试，把自动降级的逻辑越堆越复杂，反而更难解释到底走了哪条路。这一段没有对外发版——不稳定的东西不该上线。

**v2.5.1 —— 推翻重做，也是最深的一次检修**
把翻译彻底拆成三条独立路线，删掉那个"什么都会自动试一遍"的混合模式：花不花钱、走不走网，必须由使用者自己决定。免费在线路线从零实测了四个候选接口，最终落在 MyMemory，配一条全程免费的兜底链，做到境内直连、零成本、开箱即用。

这一版的转折点来自两位内部测试人员的独立验证。**Zhou-YanTong（澳门科技大学）** 和 **Wang-Shunan（北京语言大学）** 各自在干净环境里跑了一遍，撞出来的问题都落在提示上：一台完全没配 Key 的机器上，界面反复给出「[未配置 API Key]」；另一台配了 Key 的机器上，隔三差五只得到一句「[云端不可用]」。同一句话在不同机器上给出完全不同的结论，才让人意识到那条自动降级链自己也不知道走到了哪一级、为什么失败。

显卡那处是我自己在另一台没有 N 卡的机器上撞见的：明明没有卡，程序仍然告诉用户"已检测到显卡"。

于是 GPU 探测改成三路判断（CUDA 设备 / `nvidia-smi` / WMI 显卡列表），文案按真实结论分两套；Key 只认用户自己的环境变量和设置页。这几处如果没被撞出来，软件会在别人电脑上以一种很难解释的方式坏掉。

**v2.5.5 —— 把"能用"推到"好用"**
这一版处理三个长期欠账。一是 API 引擎：两个 Key 都配时以前永远只走 DeepSeek，有道等于白配，现在给了显式选择（含自动兜底）。二是界面清晰度：进程声明 DPI 感知并按真实 DPI 缩放，高分屏不再糊成一片，字体、控件、窗口一起放大。三是更新链路：程序启动后会静默检查新版本，弹窗介绍更新内容，可取消、可跳过该版本；确认后后台下载并覆盖安装，用户配置与 API Key 全部保留。

顺手清掉一处历史遗留：早年的 auto 降级模式删掉之后，状态栏仍会在 API 模式下提示「auto功能失效」，这句话现在没有意义，改为显示当前实际使用的 API 引擎。

**v2.5.6 —— 识别引擎的通用增强**
修复识别历史被覆盖的老问题；给识别引擎加上自适应门限、远场增益与降噪，专门对付远场、口音、嘈杂环境下的错听，并开放自定义热词。同时精简注释与重复样板，把四个隐藏入口收拢为统一的「独家模块」编号。

**v2.5.7 —— 更新链路的工程债**
仓库更名为 `HearizonSync`，更新地址同步跟进（旧链接由 GitHub 自动跳转，已装的用户不会掉队）。下载从单连接改成最多 8 路并发分段，国内网络下实测明显提速；中途断网不用从头再来，重试会接着已下好的分段继续；进度条开始显示实时速度与剩余时间。

**v3.0.0 —— 把「听得清」重做一遍**
这一版的触发点是两个具体现象：课堂上把 *Spanish* 听成 *fan*，以及开着空调时字幕永远不收句。追下去发现它们各自对应一个建模错误——前者是词首擦音被能量门限切掉，后者是把「绝对电平」当成了「是否有人在说话」的充分条件。

于是把音频前端整体重写，并拆成两个独立开源的核心：**HAE-VAD Core** 负责切得准（自适应噪声底、过零率互证、词首回补），**HAE-NSG Core** 负责听得清（两簇噪声门、增益与静音解耦、预加重保电平）。两个核心都是 Python + C++ 双实现、逐位一致、可单独引用的库，本项目只是它们的第一个使用者。

回灌到主程序后，旧链路「把底噪放大 8 倍」的缺陷一并修掉。此外翻译加入上下文、自定义 API 地址与流式同传，界面加入可选的对话式布局。

## 已知限制

| 限制 | 说明 |
|---|---|
| **不是真·同传** | 是"说完一句译一句"，端到端延迟 1~2 秒。真·边说边译需要流式识别配增量翻译，复杂度是另一个量级 |
| **不是医疗器械** | 不得作为助听器、听力诊断设备或任何医疗用途使用或宣称 |
| **专业术语仍会错** | SenseVoice CER 约 8%，生僻专业词仍可能听错。可在设置里填热词缓解，所有 ASR 都有这个问题 |
| **本地翻译只覆盖英→中** | opus-mt 是单语言对模型；其他语言对请用在线翻译（免费）或 API 模式 |
| **免费在线有每日额度** | 匿名 5000 字符/天，填邮箱 50000。超了自动降级，不中断 |
| **多人同时说话会乱** | 能量 VAD 不区分说话人，重叠语音会混成一句 |
| **只支持麦克风输入** | 系统声音需要 VB-Cable 之类虚拟声卡（见上文） |
| **日/韩走 Whisper** | 本版 sherpa-onnx 的 SenseVoice `language` 参数无效，为避免误判只能换引擎，代价是慢一些 |

## 同系列项目

Hearizon 不是一个程序，是一条链路。三部分各自独立开源，可以只用其中一块：

| 项目 | 作用 | 语言 |
|---|---|---|
| [**Hearizon Sync**](https://github.com/eyru/HearizonSync)（本项目） | 实时字幕翻译软件，把识别、翻译、界面串起来 | Python |
| [**HearizonSync C.R.V.**](https://github.com/eyru/HearizonSync-CRV) | 同一产品的 C++ 重写版，功能对齐、体积更小、更抗反编译 | C++ |
| [**HAE-NSG Core**](https://github.com/eyru/HAE-NSG-Core) | 音频前端：噪声抑制与增益，让声音听得清 | Python + C++ |
| [**HAE-VAD Core**](https://github.com/eyru/HAE-VAD-Core) | 音频前端：语音活动检测与切句，让句子切得准 | Python + C++ |

完整链路的顺序是：

```
麦克风 → HAE-NSG（增益与降噪）→ HAE-VAD（切句）→ 识别 → 翻译 → 字幕
```

前两级决定后两级的上限。这也是 3.0 把力气全部花在音频前端的原因：识别模型再好，
喂进去的音频里没有那个音素，它也只能猜。
