## 零、先纠正一个概念：能不能「蒸馏」有道 / 讯飞？

**答案：不能蒸馏它们的模型，但可以调用它们的 API。**

### 为什么不能

**「蒸馏」在机器学习里有严格定义**：用一个大模型（teacher）的**输出概率分布**去训练一个小模型（student），让小模型模仿大模型。

**它需要大模型的权重和 logits（输出概率）。**

而讯飞输入法、有道翻译的模型都在**服务器**上，客户端只是个壳。你能拿到的只有最终的**文字结果**，拿不到权重、拿不到 logits。

### 三个容易混淆的概念

| 你以为的 | 实际叫什么 | 可行性 |
|---|---|---|
| 蒸馏有道翻译的模型 | ❌ 概念不成立 | 拿不到权重 |
| **用有道输出训练自己的模型** | **数据蒸馏 / 知识迁移** | ⚠️ 需几十万条平行语料，且**违反服务条款** |
| **直接调有道 API** | **API 集成** | ✅ **合法、简单、马上能用** |
| 蒸馏讯飞输入法的语音识别 | ❌ 概念不成立 | 同上 |

### 如果真想「借」它们的识别能力

唯一合法路径是：用它们的 API 处理音频 → 存下（音频，文本）对 → 微调开源模型。

**但**：
- 需要至少**几千小时**标注音频
- 大部分 API 的服务条款**禁止用输出训练竞品**
- 成本远高于直接用开源模型

**→ 结论：不走这条路。**

## 一、当前实现的真实水平（鱼鱼实测）

### 1.1 识别（Whisper small）

| 指标 | 实测值 |
|---|---|
| 英文 RTF | 0.53（base 是 0.20） |

| 指标 | 实测值 |
|---|---|
| 单句耗时 | 0.77 ~ 1.19 秒 |
| 质量 | 自然、流畅 |
| 成本 | 约 ¥0.001/千字 |

|---|---|---|---|---|

| 中文 4.7 s → 英文 | 1.69 s | 1.19 s | **2.88 s** | **0.61** |

## 二、🔥 最值得改的一件事：换掉 Whisper

### 2.1 数据对比

| 模型 | 中文 CER（越低越好） | CPU 速度 | 体积 | 来源 |
|---|---|---|---|---|
| **Whisper small**（当前） | **约 20–30%** | 0.53× RTF | 480 MB | 鱼鱼实测 |
| **SenseVoice-Small**（阿里达摩院） | **7.99–8.01%** | **17–20 倍实时** | **254 MB** | FunASR 官方 |

> 数据来源：
> - [FunASR 官方博客：轻量语音识别](https://www.funasr.com/blog/lightweight-speech-recognition-cpu.html)
> - [SenseVoiceSmall-GGUF 模型卡](https://huggingface.co/FunAudioLLM/SenseVoiceSmall-GGUF)
> - [FunASR vs Whisper 实测讨论](https://github.com/modelscope/FunASR/discussions/2947)

### 2.2 这意味着什么

| 维度 | 提升 |
|---|---|
| 中文准确率 | **约 3 倍** |
| 速度 | **约 20 倍**（CPU 上 17–20 倍实时） |
| 体积 | **减半**（254 MB） |

**SenseVoice 的额外能力**：
- 中文原生训练（不是从英文模型迁过来的）
- 自带**情感识别**（中性/高兴/生气/悲伤）
- 自带**音频事件检测**（笑声、掌声、音乐、咳嗽等）

### 2.3 为什么 SenseVoice 比 Whisper 强这么多

**训练数据不同**：
- Whisper 是 OpenAI 用**多语言混合**数据训的，中文只占一部分
- SenseVoice 是**中文为主**训练，专门针对中文优化

**这对听力学 / 言语康复场景特别重要** —— 中文声调、语流音变，Whisper 经常处理不好。

## 三、第二个值得改的：用 GPU

### 3.1 主人的硬件（已实测）

| 项 | 值 |
|---|---|
| GPU | **NVIDIA GeForce RTX 5070 Ti Laptop** |
| 显存 | **12,227 MiB（约 12 GB）** |
| 驱动 | 617.14 |
| CPU | AMD Ryzen 9 9955HX（16 核 32 线程） |
| 内存 | 31.2 GB |

> ⚠️ 注：`Win32_VideoController` 报的 `AdapterRAM = 4 GB` 是 **Windows 的老 bug**，实际以 `nvidia-smi` 的 12,227 MiB 为准。

### 3.2 GPU 能带来什么

| 场景 | CPU | GPU（估算） |
|---|---|---|
| SenseVoice-Small | 17–20 倍实时 | **100+ 倍实时** |
| Whisper small | 0.53 RTF | **10–20 倍实时** |
| 可用模型大小 | 受限于 CPU | **可上 medium / large** |

### 3.3 代价

| 项 | 说明 |
|---|---|
| 装 CUDA 版 torch | 约 **2–3 GB** 下载 |
| 首次配置 | 需要匹配 CUDA 版本 |
| 功耗 | 笔记本 GPU 会明显发热耗电 |

**但考虑到 12 GB 显存，这是值得的。**

## 四、有道翻译 API：完整技术规格

### 4.1 基本信息（已从官方文档核实）

| 项 | 值 |
|---|---|
| 地址 | `https://openapi.youdao.com/api` |
| 方法 | GET / POST |
| 格式 | 表单（form） |
| 编码 | UTF-8 |
| 响应 | JSON |
| 单次上限 | **5000 字符** |
| 每小时上限 | 100 万次 / 120 万字符 |

> 来源：[有道智云文本翻译 API 文档](https://ai.youdao.com/DOCSIRMA/html/trans/api/wbfy/index.html)

### 4.2 签名算法（最容易错的地方）

```
sign = sha256(appKey + input + salt + curtime + appSecret)
signType = "v3"
```

**⚠️ 注意：input 不是原文，而是截断后的文本：**

```
如果 len(q) <= 20：  input = q
如果 len(q) >  20：  input = q前10字符 + str(len(q)) + q后10字符
```

**三个坑**：
1. `len(q)` 是**字符数**不是字节数（中文一个字算 1）
2. `salt` 必须每次随机（官方要求 UUID，因为 salt+curtime 防重放）
3. `curtime` 是 **UTC 秒级**时间戳，不是毫秒

### 4.3 请求参数

| 字段 | 必填 | 说明 |
|---|---|---|
| `q` | ✅ | 待翻译文本（UTF-8） |
| `from` | ✅ | 源语言，可设 `auto` 自动检测 |
| `to` | ✅ | 目标语言 |
| `appKey` | ✅ | 应用 ID |
| `salt` | ✅ | 随机字符串（UUID） |
| `sign` | ✅ | 签名 |
| `signType` | ✅ | 固定 `v3` |
| `curtime` | ✅ | UTC 秒级时间戳 |
| `domain` | ❌ | **领域翻译**，见下表 |
| `vocabId` | ❌ | 自定义术语表 ID |
| `strict` | ❌ | 是否严格按 from/to 翻译 |

### 4.4 ⭐ 领域翻译（DeepSeek 没有的能力）

| 取值 | 领域 |
|---|---|
| `general` | 通用（默认） |
| `computers` | 计算机 |
| **medicine** | **医学** ← 对听力学 / 言语康复有用 |
| `finance` | 金融经济 |
| `game` | 游戏 |

> ⚠️ 仅支持**中英互译**，且需在控制台开通

### 4.5 支持语言

覆盖 **100+ 语种**，包括中文（简/繁）、英、日、韩、法、德、俄、西班牙、阿拉伯等。

### 4.6 价格

| 套餐 | 价格 | 额度 |
|---|---|---|
| 新用户注册 | **免费 50 元体验金** | — |
| 入门版 | **免费** | 100 次/天 |
| 基础版 | 8 元/月 | 1 万次 |
| 500 万字符包 | 204 元 / 90 天 | — |
| 短语音翻译 API | **0.019 元/次** | 按量 |

> 来源：[有道智云翻译报价](https://ai.youdao.com/DOCSIRMA/html/trans/price/wbfy/)、[有道短语音翻译](https://ai.youdao.com/new/product-sst.s)

### 4.7 ⚠️ 但是：换有道未必更好

**有学术论文做过对比**（MQM 质量评估框架，五个维度：语言流畅性、信息准确性、词汇适当性、风格一致性、文化元素处理）：

- **大模型**：ChatGPT、文心一言、**DeepSeek**
- **传统 NMT**：百度翻译、**有道翻译**、DeepL

> 来源：[AI大语言模型与传统机器翻译对比研究](https://cnki.istiz.org.cn/kcms/detail/detail.aspx?filename=ZGTK202511013044&dbcode=CPFD&dbname=CPFD2026)

**结论：大模型时代，传统 NMT 通常不占优势。**

### 4.8 鱼鱼的建议

| 方案 | 适用场景 |
|---|---|
| **DeepSeek（当前）** | ✅ 日常同传，便宜、质量够、支持流式 |
| **有道 API** | 🟡 只在两种情况下值得加：① 要**医学领域**翻译；② 想**双引擎对比** |

**换有道不是为了「更好」，是为了「多一个选择」。**

## 五、改进清单（按性价比排序）

| 优先级 | 改什么 | 收益 | 成本 | 风险 |
|---|---|---|---|---|
| 🔥 **P0** | **Whisper → SenseVoice** | 中文准确率 **3 倍**，速度 **20 倍**，体积减半 | 中（装 FunASR + 254 MB 模型） | 低 |
| 🔥 **P1** | **上 GPU** | 速度再快 5–10 倍，可用更大模型 | 中（CUDA torch 2–3 GB） | 中（配置可能踩坑） |
| 🟡 P2 | 接有道双引擎 | 多一个对比选项 + 医学领域 | 低（但要申请 appKey） | 低 |
| 🟡 P3 | 流式识别（边说边出字） | 延迟从 1–3 秒降到 0.5 秒内 | **高**（需重写架构） | **高** |
| 🟢 P4 | 系统声音输入（VB-Cable） | 能翻网课/视频 | 中（要装虚拟声卡） | 中 |
| 🟢 P5 | 语音播报译文（TTS） | 可闭眼听 | 低（Windows 自带 TTS） | 低 |

## 六、已知限制（当前版本）

| 限制 | 说明 | 能否改 |
|---|---|---|
| **不是真·同传** | 说完一句译一句，延迟 1–3 秒 | 能，但要重写架构（P3） |
| **中文专业术语会听错** | base 把「声学」听成「生学」 | **换 SenseVoice 可大幅改善** |
| **需要联网翻译** | 识别离线，翻译走 API | 可改本地翻译模型，但质量会降 |
| **多人同时说话会乱** | 能量 VAD 不区分谁在说 | 能，但要上说话人分离（复杂） |
| **只支持麦克风** | 系统声音需 VB-Cable | 能（P4） |
| **背景噪声大时误触发** | 能量 VAD 简单 | 能，换 Silero VAD（神经网络） |

## 七、鱼鱼的建议顺序

**如果只能改一件事 → 换 SenseVoice（P0）。**

理由：
1. 中文准确率 3 倍提升，这是**质变**不是量变
2. 速度 20 倍，意味着**可以用更大的模型**（在 GPU 上）
3. 体积减半
4. 这是阿里达摩院**开源**的，免费、无法律风险

**如果改两件 → P0 + P1（SenseVoice + GPU）。**

**有道翻译（P2）优先级最低** —— 因为 DeepSeek 已经够好，有道只在「医学领域」和「双引擎对比」两种场景有价值。
